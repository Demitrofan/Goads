# Цикл сбора: sequence-диаграмма

> Источник: `services/ads/service.py` — функции `run_cycle`, `collect`, `process_new`,
> `prefetch_answers`, `find_exact_duplicate`, `trash_reason`, `find_similar_*`, `create_listing`, `save_photos`;
> `services/ads/llm.py` — `parse_ad`.

Служба сбора при старте один раз находит все 34 канала (`resolve_channels`), затем каждые 10 минут
выполняет цикл `run_cycle`: **сбор → разбор → фото**. Сайт в цикле не участвует — он читает уже готовые
объявления из базы.

```mermaid
sequenceDiagram
    autonumber
    participant TG as Telegram<br/>(34 канала)
    participant S as Служба сбора
    participant DB as SQLite
    participant LLM as OpenRouter (LLM)
    participant FS as Папка фото
    actor U as Пользователь
    participant W as Сайт (Django)

    Note over S: Шаг 1. Сбор — collect()
    loop каждый канал
        S->>DB: Номер последнего сохранённого сообщения канала
        S->>TG: Сообщения новее него (при первом запуске — за 2 дня)
        TG-->>S: Сообщения (альбомы собираются по grouped_id)
        S->>S: Пропустить текст короче 60 символов
        S->>DB: Сохранить Post (status = new, text_hash = SHA-1 нормализованного текста)
    end

    Note over S: Шаг 2. Разбор — process_new()
    S->>DB: Сообщения new/error старше 7 дней → trash, причина "old"
    S->>DB: Взять сообщения new/error по дате

    loop пачка по 32 сообщения
        S->>DB: Есть ли точный дубль (тот же text_hash за 30 дней)?
        par до 8 запросов одновременно, только для не-дублей
            S->>LLM: Промпт + текст (до 4000 символов), JSON-режим, temperature 0
            LLM-->>S: JSON: kind, village, цены, rooms, удобства, поля байка/вещи, items
        end
        S->>S: Привести ответ к типам (_clean): цифры, допустимые значения
    end

    loop каждое сообщение
        alt точный дубль, у прошлого сообщения есть объявления
            S->>DB: Привязать к тем же объявлениям, сдвинуть last_seen, status = dup
        else точный дубль мусора
            S->>DB: status = trash, причина как у прошлого сообщения (или "dup_trash")
        else LLM не ответил (3 попытки)
            S->>DB: status = error — повтор в следующем цикле
        else trash_reason() вернул причину
            S->>DB: status = trash + причина (seek, no_price, rent_too_cheap…)
        else годное объявление (или прайс-лист → по позиции на карточку)
            loop каждая позиция
                S->>DB: Найти похожее: те же ключевые поля, текст совпадает на 75 %+ (30 дней)
                alt похожее найдено
                    S->>DB: Склеить: привязать сообщение, сдвинуть last_seen
                else похожего нет
                    S->>DB: Создать Listing / MotoListing / StuffListing<br/>(для байка — характеристики из справочника)
                end
            end
            S->>DB: status = parsed, если создана хотя бы одна карточка, иначе dup
        end
    end

    Note over S: Шаг 3. Фото — save_photos()
    loop каждая новая карточка
        opt фото сообщения ещё не скачаны в этом цикле
            S->>TG: Скачать до 6 фото (из видео — обложку)
            TG-->>S: Файлы
            S->>FS: Уменьшить до 1280 px, сохранить JPEG
        end
        S->>DB: Записать пути фото (позиции прайс-листа делят общие фото)
    end
    S->>S: Записать итоги цикла в журнал, пауза 10 минут

    Note over U,W: В любой момент, независимо от цикла
    U->>W: Открыть /rent/, /moto/ или /stuff/ с фильтрами
    W->>DB: Объявления за период по last_seen, с фото и числом источников
    W-->>U: Карточки с ценами в выбранной валюте
```

## Обработка сбоев

| Ситуация | Поведение |
|---|---|
| Telegram просит подождать (FloodWait) | Служба ждёт указанное время, канал пропускается до следующего цикла |
| Канал недоступен или переименован | Ошибка в журнал, остальные каналы собираются |
| LLM вернул ошибку сети / 5xx | До 3 попыток с паузой 5, 10, 15 с; затем `status = error` и повтор в следующем цикле |
| LLM не поддерживает JSON-режим (HTTP 400) | Повтор без `response_format`, JSON просится текстом промпта |
| Неверный ключ или кончились деньги (HTTP 401/402/403) | Цикл прерывается, ошибка в журнал; неразобранные сообщения остаются `new`/`error` и разберутся после пополнения (если не устареют за 7 дней) |
| Фото не скачалось | Предупреждение в журнал, карточка остаётся без этого фото |
| Сообщение собрано в прошлом цикле, фото нет в памяти | Альбом запрашивается заново по номерам сообщений (`msg_id … msg_id + 9`) |
| Запущен второй экземпляр службы | Он видит блокировку `logs/service.lock` и сразу завершается |

## Почему так

- **Дубли отсекаются до LLM**: в базе дублей больше, чем разобранных объявлений — это прямая экономия денег
  ([ADR-0002](adr/0002-llm-instead-of-rules.md)).
- **Запросы к LLM — пачками и параллельно**: последовательный разбор недели сообщений занял бы часы.
- **Фото скачиваются только для новых карточек**: у дублей и мусора фото не нужны.
