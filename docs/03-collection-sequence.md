# Цикл сбора: sequence-диаграмма

> Источник: `services/ads/service.py` — функции `run_cycle`, `collect`, `backfill`, `process_new`,
> `prefetch_answers`, `ask_gpt`, `find_exact_duplicate`, `trash_reason`, `find_similar_*`, `create_listing`,
> `save_photos`, `check_closed`; `services/ads/llm.py` — `parse_ad`; `ads/bot.py` — `notify`; `ads/monitor.py`.

Служба сбора при старте один раз находит все 55 каналов четырёх регионов (`resolve_channels`), затем каждые
10 минут выполняет цикл `run_cycle`: **сбор → догрузка истории → разбор → фото → рассылка бота**, а каждый
18-й цикл (~3 часа) ещё и **проверку «снято»**. Сайт в цикле не участвует — он читает уже готовые объявления из базы.

```mermaid
sequenceDiagram
    autonumber
    participant TG as Telegram<br/>(55 каналов)
    participant S as Служба сбора
    participant DB as SQLite
    participant LLM as OpenRouter (LLM)
    participant FS as Папка фото
    participant B as Бот (Bot API)
    actor U as Пользователь

    Note over S: Шаг 1. Сбор — collect()
    loop каждый канал
        S->>DB: Номер последнего сохранённого сообщения канала
        S->>TG: Сообщения новее него (при первом запуске — за 2 дня)
        TG-->>S: Сообщения (альбомы собираются по grouped_id)
        S->>S: Пропустить текст короче 60 символов
        S->>DB: Сохранить Post (status = new, text_hash = SHA-1 нормализованного текста)
    end

    Note over S: Шаг 2. Догрузка истории — backfill() (только Армения, Грузия, Пхукет)
    loop канал, история которого не дочитана
        S->>TG: 100 сообщений старше самого раннего сохранённого
        S->>DB: Сохранить Post, дошли до 14 дней назад — канал готов
    end

    Note over S: Шаг 3. Разбор — process_new()
    S->>DB: new/error старше срока (Гоа 7 дней, иначе 14) → trash, причина "old"
    S->>DB: Взять сообщения new/error по дате

    loop пачка по 32 сообщения
        S->>DB: Есть ли точный дубль (тот же text_hash за 30 дней)?
        par до 8 запросов одновременно, только для не-дублей
            S->>LLM: Подсказка региона + текст (до 4000 символов), JSON-режим, temperature 0
            LLM-->>S: JSON: kind, city, village, цены, currency, rooms, удобства, поля байка/вещи, items
        end
        S->>S: Привести ответ к типам (_clean), вне Гоа — цена → рупии, место → город + район
    end

    loop каждое сообщение
        alt точный дубль, у прошлого сообщения есть объявления
            S->>DB: Привязать к тем же объявлениям, сдвинуть last_seen, status = dup
        else точный дубль мусора
            S->>DB: status = trash, причина как у прошлого сообщения (или "dup_trash")
        else LLM не ответил (3 попытки)
            S->>DB: status = error — повтор в следующем цикле
        else trash_reason() вернул причину
            S->>DB: status = trash + причина (seek, no_price, car, th_sale…)
        else годное объявление (или прайс-лист → по позиции на карточку)
            loop каждая позиция
                S->>DB: Найти похожее того же региона: те же ключевые поля, текст совпадает на 75 %+ (30 дней)
                alt похожее найдено
                    S->>DB: Склеить: привязать сообщение, сдвинуть last_seen, снять пометку «снято»
                else похожего нет
                    S->>DB: Создать Listing / MotoListing / StuffListing<br/>(для байка — код модели и характеристики из справочника)
                end
            end
            S->>DB: status = parsed, если создана хотя бы одна карточка, иначе dup
        end
    end

    Note over S: Шаг 4. Фото — save_photos()
    loop каждая новая карточка
        opt фото сообщения ещё не скачаны в этом цикле
            S->>TG: Скачать до 6 фото (из видео — обложку)
            TG-->>S: Файлы
            S->>FS: Уменьшить до 1280 px, сохранить JPEG
        end
        S->>DB: Записать пути фото (позиции прайс-листа делят общие фото)
    end

    Note over S: Шаг 5. Рассылка — bot.notify()
    S->>DB: Подписки, новые карточки за 24 ч под их фильтры (тот же build_queryset, что у сайта)
    S->>B: До 10 объявлений на подписку, дальше — ссылка на список
    B-->>U: Сообщение в Telegram

    opt каждый 18-й цикл (~3 ч) — check_closed()
        S->>DB: Неснятые объявления за 30 дней и их сообщения
        S->>TG: Перечитать сообщения, по 100 на канал за запрос
        S->>DB: Все удалены или дописано «сдано/продано» → closed = сейчас
    end
    S->>S: Итоги цикла в журнал, отметка logs/heartbeat, пауза 10 минут
```

## Обработка сбоев

| Ситуация | Поведение | Владелец узнаёт |
|---|---|---|
| Telegram просит подождать (FloodWait) | Служба ждёт указанное время, канал пропускается до следующего цикла | — |
| Канал недоступен или переименован | Ошибка в журнал, остальные каналы собираются | — (видно в журнале: «Каналов доступно: N из 55») |
| LLM вернул ошибку сети / 5xx | До 3 попыток с паузой 5, 10, 15 с; затем `status = error` и повтор в следующем цикле | — |
| LLM не поддерживает JSON-режим (HTTP 400) | Повтор без `response_format`, JSON просится текстом подсказки | — |
| Неверный ключ или кончились деньги (HTTP 401/402/403) | Цикл прерывается; неразобранные сообщения остаются `new`/`error` и разберутся после пополнения (если не устареют) | Тревога сразу; остаток < $1 — тревога заранее |
| Telegram-сессия разлогинилась | Сборщик не стартует, служба перезапускает его раз в 10 минут | Тревога сразу |
| Цикл упал с исключением | Ошибка в журнал, следующий цикл через 10 минут | Тревога сразу |
| Сборщик завис или служба остановлена | — | Сторож: нет отметки цикла > 40 минут или служба не активна |
| Фото не скачалось | Предупреждение в журнал, карточка остаётся без этого фото | — |
| Сообщение собрано в прошлом цикле, фото нет в памяти | Альбом запрашивается заново по номерам сообщений (`msg_id … msg_id + 9`) | — |
| Запущен второй экземпляр службы | Он видит блокировку `logs/service.lock` и сразу завершается | — |
| Служба перезапущена посреди цикла | Объявления оборванного цикла остаются без фото — перезапуск только на паузе | — |

Повтор одной тревоги — не чаще раза в 3 часа, после починки приходит «✅ Снова работает» ([ADR-0007](adr/0007-telegram-monitoring.md)).

## Почему так

- **Дубли отсекаются до LLM**: треть потока — точные повторы; это прямая экономия денег
  ([ADR-0002](adr/0002-llm-instead-of-rules.md), [цифры](06-metrics.md)).
- **Запросы к LLM — пачками и параллельно**: последовательный разбор ~1 150 сообщений в сутки
  после простоя растянулся бы на часы.
- **История догружается по 100 сообщений за цикл**: у новых регионов сразу есть объявления за 2 недели,
  а Telegram не получает всплеск запросов.
- **Фото скачиваются только для новых карточек**: у дублей и мусора фото не нужны.
- **Бот использует фильтры сайта**: одна логика отбора — нет расхождений «на сайте есть, а бот не прислал».
