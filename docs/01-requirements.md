# Спецификация требований

> Источники: `services/ads/service.py`, `services/ads/llm.py`, `ads/views.py`, `moto/views.py`,
> `stuff/views.py`, `ads/currency.py`, `goads/settings.py`, `goads/urls.py`.
> Требования описывают систему в её текущем виде (ретроспективная спецификация).

## 1. Проблема

Русскоязычные жители и туристы Гоа (Индия) ищут жильё, байки и вещи через Telegram. Объявления:

- разбросаны по десяткам каналов и чатов;
- написаны в свободной форме, смесью русского и английского, со сленгом («2bhk Морджим 45к, кондей, вайфай»);
- дублируются в разных каналах, часто с небольшими правками;
- за пару дней уходят вниз ленты.

Искать и сравнивать их нельзя: запрос «1-комнатные в Арамболе до 40 000 ₹ с кондиционером» в Telegram не сделать.

**Цель:** собрать объявления в одном месте в структурированном виде, с поиском и фильтрами,
без ручного труда и при расходах в единицы долларов в месяц.

## 2. Заинтересованные лица и пользователи

| Роль | Кто | Что нужно |
|---|---|---|
| Ищущий жильё / байк / вещь | Русскоязычные в Гоа, десятки человек («для своих»), чаще с телефона | Быстро найти актуальные предложения с понятной ценой и перейти к автору в Telegram |
| Владелец сайта | Автор проекта, он же администратор | Сбор без участия человека, низкие и предсказуемые расходы, контроль качества разбора через админку Django |
| Авторы объявлений | Арендодатели, прокатчики, продавцы в Telegram | Не участвуют напрямую; сайт ведёт на их исходное сообщение |

## 3. Границы системы

**Входит:** сбор сообщений из публичных Telegram-каналов, разбор текста, отсев мусора и дублей,
хранение, сайт с поиском и карточками, показ цен в нескольких валютах.

**Не входит:** публикация объявлений на сайте самими пользователями, переписка, оплата, бронирование,
модерация вручную каждого объявления, мобильное приложение.

## 4. Функциональные требования

### Сбор и обработка (служба сбора)

| ID | Требование |
|---|---|
| FR-01 | Система собирает новые сообщения из 34 Telegram-каналов (списки по разделам: жильё 14, байки 9, барахолка 11; пересечения убираются). |
| FR-02 | Сбор продолжается с последнего сохранённого сообщения канала; при первом запуске берётся история за 2 дня. |
| FR-03 | Альбом (несколько фото с общим `grouped_id`) сохраняется как одно сообщение; текст берётся из первого сообщения альбома с текстом. |
| FR-04 | Сообщения короче 60 символов не сохраняются. |
| FR-05 | Точный дубль (тот же нормализованный текст за последние 30 дней) привязывается к уже существующим объявлениям без обращения к LLM. |
| FR-06 | Остальные сообщения разбираются LLM в JSON: вид объявления, посёлок, цены, комнаты, удобства; для байков — модель, тип, год, условия; для вещей — название, категория, состояние, цена. |
| FR-07 | Сообщение, не ставшее объявлением, помечается мусором с причиной (см. [состояния](05-post-states.md)). |
| FR-08 | Прайс-лист (несколько объектов со своими ценами) даёт отдельную карточку на каждую годную позицию, не больше 15. |
| FR-09 | Новое сообщение, похожее на существующее объявление, склеивается с ним (см. BR-05), а не создаёт новую карточку. |
| FR-10 | Для байка характеристики (объём, мощность, вес) подставляются из справочника моделей по названию. |
| FR-11 | Для новой карточки сохраняется до 6 фото; из видео берётся обложка. |
| FR-12 | При сбое LLM сообщение помечается ошибкой и разбирается повторно в следующем цикле. |
| FR-13 | Цикл повторяется каждые 10 минут. |

### Сайт

| ID | Требование |
|---|---|
| FR-20 | Главная страница ведёт в три раздела: жильё `/rent/`, байки `/moto/`, барахолка `/stuff/`. |
| FR-21 | **Жильё:** фильтры — цена за месяц или за сутки (от/до), комнаты (комната, студия, 1–3 BHK, 4+ BHK), посёлок, удобства (8 шт.), слова в тексте, период публикации. |
| FR-22 | **Байки:** фильтры — цена за месяц / за сутки / продажи, тип (скутер, мотоцикл), модель, условия (шлем, доставка, без залога, без паспорта), слова, период. |
| FR-23 | **Барахолка:** фильтры — цена (от/до; «до N» включает бесплатное), «даром», категория (7 шт.), состояние (новое, б/у), слова (в тексте и названии), период. |
| FR-24 | Период публикации: за сутки, 3 дня, неделю, месяц. По умолчанию: жильё — неделя, байки и барахолка — месяц. Считается по последнему появлению объявления (`last_seen`). |
| FR-25 | Сортировка: сначала свежие (по умолчанию), сначала дешёвые, сначала дорогие. По 48 карточек на странице; пагинация сохраняет фильтры. |
| FR-26 | В списках жилья и байков показываются только объявления с ценой по выбранному типу цены. |
| FR-27 | Карточка объявления: поля разбора, фото, полный текст, ссылки на все исходные сообщения в Telegram (от новых к старым). В списке у карточки показывается число источников, если их больше одного. |
| FR-28 | Цены показываются в выбранной валюте: ₽ (по умолчанию), Br, ₴, $, ₹. Выбор запоминается на год. Фильтр цены вводится в выбранной валюте. |
| FR-29 | Вход по паролю можно включить настройкой (`SITE_LOGIN_REQUIRED`); сессия входа — полгода. |
| FR-30 | Администратор просматривает и правит сообщения и объявления через админку Django. |

## 5. Бизнес-правила

| ID | Правило | Где в коде |
|---|---|---|
| BR-01 | Цены хранятся только в рупиях; перевод в другие валюты — при показе. Округление: ₽ до сотен, ₴ до десятков, остальные до единиц. | `ads/currency.py` (`ROUND_TO`) |
| BR-02 | Сообщения старше 7 дней не разбираются и уходят в мусор с причиной `old`. | `MAX_AGE_DAYS` |
| BR-03 | Нормализация для дублей: нижний регистр, без ссылок, @ников, телефонов, эмодзи и знаков препинания; хэш SHA-1. | `normalize`, `text_hash` |
| BR-04 | Объявлением становятся только виды `rent`, `bike`, `sale`. Остальные (`seek`, `car`, `property_sale`, `work`, `service`, `exchange`, `visa`, `other`) — мусор с причиной, равной виду. | `trash_reason` |
| BR-05 | Склейка похожих (окно 30 дней, текст совпадает на 75 % и больше): жильё — тот же посёлок, комнаты, цена за месяц и за сутки (нужны посёлок и хотя бы одна цена); байк — та же модель и все три цены (нужна модель); вещь — то же название и цена (нужно название). | `find_similar_*` |
| BR-06 | Жильё и байк без цены — мусор (`no_price`, `bike_no_price`); для байка годится и цена продажи. | `trash_reason` |
| BR-07 | Вещь без названия — `sale_no_title`; без цены и не «даром» — `sale_no_price`. | `trash_reason` |
| BR-08 | Жильё дешевле 3 000 ₹/мес — мусор `rent_too_cheap`; жильё без указания комнат дешевле 10 000 ₹/мес — мусор `rent_cheap_no_rooms` (так выглядят байки, о которых говорит только фото). См. [ADR-0004](adr/0004-cheap-rent-to-trash.md). | `RENT_MIN_MONTH`, `RENT_MIN_MONTH_NO_ROOMS` |
| BR-09 | Прайс-лист, из которого не вышло ни одной годной позиции, — мусор (`many_objects`, `bike_many`, `sale_many`). | `trash_reason` |
| BR-10 | Цена в сезон: если указаны разные цены, берётся цена высокого сезона (октябрь–март). Комиссия агента к цене не прибавляется; цена за неделю игнорируется. | промпт в `llm.py` |
| BR-11 | Цена вещи в рублях переводится в рупии умножением на 1,15. | промпт в `llm.py` |
| BR-12 | Комнаты: `room`, `1bk`, `1bhk`, `2bhk`, `3bhk`, `4bhk+` (4 и больше спален сводятся в одну категорию). | `llm.py` (`ROOMS`) |
| BR-13 | Характеристики байка из справочника: точное совпадение названия или схожесть ≥ 85 % при совпадающих числах в названии (SR 125 ≠ SR 160). | `bike_specs` |
| BR-14 | Объявление «живёт» по дате последнего появления: каждое новое сообщение-дубль сдвигает `last_seen`. | `attach` |

## 6. Нефункциональные требования

| ID | Категория | Требование | Как обеспечено |
|---|---|---|---|
| NFR-01 | Стоимость | Разбор не дороже ~$0,0001 за сообщение, порядок $1–2 в месяц | Точные дубли и старые сообщения не уходят в LLM; дешёвая модель, выбранная на эталоне ([ADR-0002](adr/0002-llm-instead-of-rules.md)) |
| NFR-02 | Актуальность | Новое объявление появляется на сайте в пределах одного цикла (≈10 мин + время разбора) | `INTERVAL_MIN = 10` |
| NFR-03 | Производительность разбора | Сообщения отправляются в LLM параллельно | 8 потоков, пачки по 32 (`LLM_WORKERS`) |
| NFR-04 | Надёжность | Сбой внешнего сервиса не останавливает систему | LLM: 3 попытки с паузой, при ошибке — повтор в следующем цикле; Telegram: ожидание при FloodWait, недоступный канал пропускается; ЦБ: запасные курсы |
| NFR-05 | Целостность | Одна Telegram-сессия используется одним процессом | Блокировка файла `logs/service.lock`; уникальность (канал, номер сообщения) в базе |
| NFR-06 | Ресурсы | Работа на VPS с 2 ГБ RAM | SQLite, лимит памяти службы сбора, фото ≤ 1280 px, JPEG 80 %, ≤ 6 шт. |
| NFR-07 | Безопасность | Ключи и сессии не попадают в репозиторий; трафик по HTTPS | `.env` и `*.session` вне git; nginx + Let's Encrypt; безопасные cookie при `SITE_HTTPS` |
| NFR-08 | Доступность для пользователя | Сайт не режется блокировщиками рекламы | Нет `ads` в адресах страниц и фото (`/rent/`, `media/photos/`) |
| NFR-09 | Удобство | Интерфейс на русском, время Гоа (Asia/Kolkata), работа с телефона | `LANGUAGE_CODE`, `TIME_ZONE` |
| NFR-10 | Заменяемость | Модель и поставщик LLM меняются без правки кода | `LLM_MODEL`, `LLM_BASE_URL` (любой API, совместимый с OpenAI) |
| NFR-11 | Наблюдаемость | Итоги каждого цикла записываются в журнал | `logs/ads_service.log`: новые, дубли, склейки, мусор, ошибки по разделам |

## 7. Известные ограничения

- Поиск по словам в SQLite не учитывает регистр только для латиницы: «Коляска» ≠ «коляска» ([ADR-0001](adr/0001-sqlite.md)).
- Аренда машин иногда попадает в байки.
- Объявления не скрываются как «сданные»: они просто перестают попадать в период фильтра.
