# Спецификация требований

> Источники: `services/ads/service.py`, `services/ads/llm.py`, `ads/views.py`, `moto/views.py`,
> `stuff/views.py`, `ads/currency.py`, `ads/places.py`, `ads/bot.py`, `ads/monitor.py`, `ads/seo.py`,
> `moto/catalog.py`, `goads/settings.py`, `goads/urls.py`, `deploy/`.
> Требования описывают систему в её текущем виде (ретроспективная спецификация, на 19.10.2026).

## 1. Проблема

Русскоязычные жители и туристы Гоа (Индия), Армении, Грузии и Пхукета (Таиланд) ищут жильё, байки и вещи
через Telegram. Объявления:

- разбросаны по десяткам каналов и чатов;
- написаны в свободной форме, смесью русского и английского, со сленгом («2bhk Морджим 45к, кондей, вайфай»);
- дублируются в разных каналах, часто с небольшими правками;
- за пару дней уходят вниз ленты, а сданное не убирается.

Искать и сравнивать их нельзя: запрос «1-комнатные в Арамболе до 40 000 ₹ с кондиционером» в Telegram не сделать.

**Цель:** собрать объявления в одном месте в структурированном виде, с поиском, фильтрами и уведомлениями,
без ручного труда и при расходах порядка $10 в месяц (сервер + разбор).

## 2. Заинтересованные лица и пользователи

| Роль | Кто | Что нужно |
|---|---|---|
| Ищущий жильё / байк / вещь | Русскоязычные в Гоа, Армении, Грузии, на Пхукете; десятки человек («для своих»), чаще с телефона | Быстро найти актуальные предложения с понятной ценой в привычной валюте и перейти к автору в Telegram |
| Подписчик бота | Тот же пользователь | Получать новые объявления под свой фильтр, не заходя на сайт |
| Владелец сайта | Автор проекта, он же администратор | Сбор без участия человека, низкие и предсказуемые расходы, узнавать о поломках сразу, контроль качества разбора через админку Django |
| Авторы объявлений | Арендодатели, прокатчики, продавцы в Telegram | Не участвуют напрямую; сайт ведёт на их исходное сообщение |

## 3. Границы системы

**Входит:** сбор сообщений из открытых Telegram-каналов и групп четырёх регионов, разбор текста, отсев мусора
и дублей, отслеживание снятых объявлений, хранение, сайт с поиском и карточками, показ цен в нескольких валютах,
Telegram-бот с подписками на поиск, сводка и тревоги владельцу, резервные копии, SEO.

**Не входит:** публикация объявлений на сайте самими пользователями, переписка, оплата, бронирование,
ручная модерация каждого объявления, мобильное приложение.

## 5. Функциональные требования

### Сбор и обработка (служба сбора)

| ID | Требование |
|---|---|
| FR-01 | Система собирает новые сообщения из 55 Telegram-источников: Гоа — 34 (списки по разделам: жильё 14, байки 9, барахолка 11; пересечения убираются), Армения — 7, Грузия — 5, Пхукет — 9 (каналы и открытые группы). Регион сообщения определяется по каналу. |
| FR-02 | Сбор продолжается с последнего сохранённого сообщения канала; при первом запуске берётся история за 2 дня. |
| FR-03 | Для регионов кроме Гоа история догружается назад до 14 дней — по 100 сообщений с канала за цикл, чтобы не нагружать Telegram. |
| FR-04 | Альбом (несколько фото с общим `grouped_id`) сохраняется как одно сообщение; текст берётся из первого сообщения альбома с текстом. |
| FR-05 | Сообщения короче 60 символов не сохраняются. |
| FR-06 | Точный дубль (тот же нормализованный текст за последние 30 дней) привязывается к уже существующим объявлениям без обращения к LLM. |
| FR-07 | Остальные сообщения разбираются LLM в JSON подсказкой своего региона: вид объявления, место (посёлок или город + район), цены и их валюта, комнаты, удобства; для байков — модель, тип, год, условия; для вещей — название, категория, состояние, цена. |
| FR-08 | Цена в валюте объявления (драм, лари, бат, $, €, ₽) переводится в рупии по курсу ЦБ РФ. |
| FR-09 | Место вне Гоа нормализуется по справочнику районов: синонимы и микрорайоны сводятся к району (Варкетили → Самгори), незнакомый «район» отбрасывается, место без города считается городом. |
| FR-10 | Сообщение, не ставшее объявлением, помечается мусором с причиной (см. [состояния](05-post-states.md)). |
| FR-11 | Прайс-лист (несколько объектов со своими ценами) даёт отдельную карточку на каждую годную позицию, не больше 15. |
| FR-12 | Новое сообщение, похожее на существующее объявление того же региона, склеивается с ним (см. BR-05), а не создаёт новую карточку. |
| FR-13 | Байк получает код модели по справочнику (41 модель): по нему работает фильтр «Модель» и подбирается картинка. Характеристики (объём, мощность, вес) подставляются из справочника `model_info`. Машины, принятые за байк, уходят в мусор. |
| FR-14 | Для новой карточки сохраняется до 6 фото; из видео берётся обложка. |
| FR-15 | При сбое LLM сообщение помечается ошибкой и разбирается повторно в следующем цикле. |
| FR-16 | Раз в ~3 часа сообщения объявлений за 30 дней перечитываются в Telegram; удалённое или дополненное словом «сдано/продано/sold» объявление помечается снятым ([ADR-0006](adr/0006-closed-listings.md)). Повторная публикация снимает пометку. |
| FR-17 | После каждого цикла новые объявления рассылаются подписчикам бота, чьи фильтры они проходят. |
| FR-18 | Цикл повторяется каждые 10 минут. |

| FR-28 | В списках жилья и байков показываются только объявления с ценой по выбранному типу цены. |

## 6. Бизнес-правила

| ID | Правило | Где в коде |
|---|---|---|
| BR-01 | Цены хранятся только в рупиях; перевод в другие валюты — при показе. Округление: ₽ и ֏ до сотен, ₴ и ฿ до десятков, остальные до единиц. | `ads/currency.py` (`ROUND_TO`) |
| BR-02 | Сообщения старше срока актуальности не разбираются и уходят в мусор с причиной `old`: Гоа — 7 дней, остальные регионы — 14 (там сдают надолго). | `MAX_AGE_DAYS`, `MAX_AGE_DAYS_EXTRA` |
| BR-03 | Нормализация для дублей: нижний регистр, без ссылок, @ников, телефонов, эмодзи и знаков препинания; хэш SHA-1. | `normalize`, `text_hash` |
| BR-04 | Объявлением становятся только виды `rent`, `bike`, `sale`. Остальные (`seek`, `car`, `property_sale`, `work`, `service`, `exchange`, `visa`, `other`) — мусор с причиной, равной виду. | `trash_reason` |
| BR-05 | Склейка похожих (окно 30 дней, текст совпадает на 75 % и больше): жильё — тот же регион, город, посёлок/район, комнаты, цена за месяц и за сутки (нужны место и хотя бы одна цена); байк — тот же регион, модель и все три цены (нужна модель); вещь — то же название и цена (нужно название). | `find_similar_*` |
| BR-06 | Жильё и байк без цены — мусор (`no_price`, `bike_no_price`); для байка годится и цена продажи. | `trash_reason` |
| BR-07 | Вещь без названия — `sale_no_title`; без цены и не «даром» — `sale_no_price`. | `trash_reason` |
| BR-08 | Жильё дешевле 3 000 ₹/мес — мусор `rent_too_cheap`; жильё без указания комнат дешевле 10 000 ₹/мес — мусор `rent_cheap_no_rooms` (так выглядят байки, о которых говорит только фото). См. [ADR-0004](adr/0004-cheap-rent-to-trash.md). | `RENT_MIN_MONTH`, `RENT_MIN_MONTH_NO_ROOMS` |
| BR-09 | Прайс-лист, из которого не вышло ни одной годной позиции, — мусор (`many_objects`, `bike_many`, `sale_many`). | `trash_reason` |
| BR-10 | Реклама проката: прайс-лист из 3+ байков с одинаковой ценой и словом «от / from» в тексте («модели от 4000 бат») — мусор `bike_list_same_price`, а не одна и та же цена на все модели. | `FROM_PRICE` |
| BR-11 | Вид объявления, которого нет в разделах региона (вещи в Армении), — мусор с причиной `<регион>_<вид>` (`am_sale`, `th_sale`). | `EXTRA_REGIONS` |
| BR-12 | Байк, чьё название — марка или модель автомобиля (Swift, Innova, Creta…), — мусор `car`. | `moto/catalog.py` (`is_car`) |
| BR-13 | Цена в сезон: если указаны разные цены, берётся цена высокого сезона (октябрь–март). Комиссия агента к цене не прибавляется; цена за неделю игнорируется. | подсказка в `llm.py` |
| BR-14 | Валюта цены вне Гоа определяется LLM по тексту (`currency`); неизвестная валюта считается рупиями. Перевод в рупии — по текущему курсу ЦБ, при недоступности — по запасным курсам. | `price_to_rupees` |
| BR-15 | Комнаты: Гоа и Пхукет — `room`, `1bk`, `1bhk`, `2bhk`, `3bhk`, `4bhk+` (на Пхукете — число спален); Армения и Грузия — `room`, `1k`…`4k+` (все комнаты, как принято там). | `llm.py` (`ROOMS`), `ads/views.py` |
| BR-16 | Характеристики байка из справочника: точное совпадение названия или схожесть ≥ 85 % при совпадающих числах в названии (SR 125 ≠ SR 160). | `bike_specs` |
| BR-17 | Объявление «живёт» по дате последнего появления: каждое новое сообщение-дубль сдвигает `last_seen`. | `attach` |
| BR-18 | Снято: удалены все исходные сообщения или в одном из них появилось слово «сдано/продано/забронировано/не актуально/rented/sold/reserved/booked/not available», которого не было в исходном тексте. | `check_closed`, `CLOSED_WORDS` |
| BR-19 | Бот не пишет о старых сообщениях (догрузка истории): только о тех, что опубликованы за последние 24 часа. | `ads/bot.py` (`FRESH_HOURS`) |

## 7. Нефункциональные требования

| ID | Категория | Требование | Как обеспечено |
|---|---|---|---|
| NFR-01 | Стоимость | Разбор не дороже ~$0,0002 за сообщение, не больше $5 в месяц | Точные дубли и старые сообщения не уходят в LLM; дешёвая модель, выбранная на эталоне ([ADR-0002](adr/0002-llm-instead-of-rules.md)); месячный лимит на ключе; тревога при остатке < $1 |
| NFR-02 | Актуальность | Новое объявление появляется на сайте в пределах одного цикла (≈10 мин + время разбора); снятое пропадает в пределах ~3 ч | `INTERVAL_MIN = 10`, `CHECK_CLOSED_EVERY = 18` |
| NFR-03 | Производительность разбора | Сообщения отправляются в LLM параллельно | 8 потоков, пачки по 32 (`LLM_WORKERS`) |
| NFR-04 | Надёжность | Сбой внешнего сервиса не останавливает систему | LLM: 3 попытки с паузой, при ошибке — повтор в следующем цикле; Telegram: ожидание при FloodWait, недоступный канал пропускается; ЦБ: запасные курсы |
| NFR-05 | Наблюдаемость | О поломке владелец узнаёт в течение 10 минут | Сторож, тревоги сборщика и утренняя сводка в Telegram ([ADR-0007](adr/0007-telegram-monitoring.md)); итоги цикла в `logs/ads_service.log` |
| NFR-06 | Сохранность данных | Потеря базы — не больше суток данных | Ночная копия `sqlite3 .backup` с `integrity_check`, 7 копий на сервере + 8 еженедельных дома |
| NFR-07 | Целостность | Одна Telegram-сессия используется одним процессом | Блокировка файла `logs/service.lock`; уникальность (канал, номер сообщения) в базе; локальный сбор отключён |
| NFR-08 | Ресурсы | Работа на VPS с 2 ГБ RAM | SQLite, лимит памяти службы сбора 700 МБ, фото ≤ 1280 px, JPEG, ≤ 6 шт. Сейчас занято ~620 МБ |
| NFR-09 | Безопасность | Ключи и сессии не попадают в репозиторий; трафик по HTTPS; бот принимает только запросы Telegram | `.env` и `*.session` вне git; nginx + Let's Encrypt; безопасные cookie при `SITE_HTTPS`; секрет в заголовке webhook |
| NFR-10 | Доступность для пользователя | Сайт не режется блокировщиками рекламы | Нет `ads` в адресах страниц и фото (`/rent/`, `media/photos/`) |
| NFR-11 | Удобство | Интерфейс на русском, время Гоа (Asia/Kolkata), работа с телефона | `LANGUAGE_CODE`, `TIME_ZONE`, адаптивная вёрстка |
| NFR-12 | Заменяемость | Модель и поставщик LLM меняются без правки кода | `LLM_MODEL`, `LLM_BASE_URL` (любой API, совместимый с OpenAI) |
| NFR-13 | Расширяемость | Новый регион — без изменения логики сбора | Записи в `EXTRA_REGIONS`, `REGIONS`, `REGION_SEO`, `REGION_PREFIXES`, файл каналов, подсказка GPT, флаг ([ADR-0005](adr/0005-regions-as-config.md)) |

## 8. Известные ограничения

- Аренда машин иногда попадает в байки, если модель машины не из справочника.
- Байк без описания, принятый за жильё, отсекается порогом цены и в раздел байков не попадает ([ADR-0004](adr/0004-cheap-rent-to-trash.md)).
- По Батуми живых каналов не нашлось — Батуми только из общегрузинского канала.
