# ADR-0001. SQLite вместо PostgreSQL

- **Статус:** принято
- **Дата:** 2026-10

## Контекст

- Сайт некоммерческий, для «своих»: десятки пользователей, нагрузка небольшая.
- Пишет в базу один процесс — служба сбора, раз в 10 минут. Сайт только читает
  (кроме входа и админки). Второй экземпляр службы запустить нельзя (блокировка файла).
- Сервер — небольшой VPS с 2 ГБ памяти, на котором уже работают nginx, Gunicorn и служба сбора.
- Владелец — один человек без опыта администрирования баз данных.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **SQLite** | Ничего не нужно устанавливать и настраивать; база — один файл, копия делается копированием; ноль памяти на отдельный сервер БД | Одна запись в момент времени; поиск без учёта регистра только для латиницы; нет полнотекстового поиска «из коробки» в Django |
| PostgreSQL | Параллельная запись, полнотекстовый поиск, регистр для кириллицы | Отдельная служба: память, настройка, обновления, резервные копии — на маленьком сервере и для одного человека это заметная нагрузка |

## Решение

Использовать SQLite (`db_rielt.db`). Код работает только через Django ORM, без особенностей конкретной СУБД,
чтобы переход на PostgreSQL сводился к смене настройки `DATABASES` и переносу данных.

## Последствия

- ➕ Развёртывание и резервное копирование — копирование одного файла.
- ➕ Нет отдельного процесса СУБД, памяти сервера хватает.
- ➖ Поиск по словам: `icontains` в SQLite не учитывает регистр только для латиницы — «Коляска» и «коляска»
  сейчас ищутся по-разному. Известное ограничение, в списке задач.
- ➖ Архитектура держится на допущении «пишет один процесс»: появление второго писателя
  (например, пользователи сами добавляют объявления) потребует пересмотра.

## Когда пересмотреть

- Нужен поиск по-русски без учёта регистра (альтернатива без смены СУБД — поле с текстом в нижнем регистре).
- Мультирегиональность: несколько служб сбора пишут параллельно.
- Пользовательские действия с записью: избранное, свои объявления, жалобы.
